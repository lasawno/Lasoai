# Business DNA form payload fix

The observed `Unrecognized Business DNA fields.` message is produced by the Python validator. It demonstrates that the submit event reached Python; it is separate from the earlier connection error. A successful Business DNA state update still needs to be verified after applying this change.

## Cause

The form controls had `name="name"`, `name="goals"`, etc. but IDs `dna-name`, `dna-goals`, etc. Reflex 0.10.0's `_handle_submit_js_template` merges native FormData entries with `_get_form_refs()` values. The latter derives keys from control IDs using `format_ref`, replacing hyphens with underscores. This creates extra payload keys `dna_name`, `dna_purpose`, `dna_goals`, `dna_responsibilities`, `dna_tools`, and `dna_rules`. The strict validator correctly rejects them, even if only the first field was filled.

The fix aligns each control's ID, name, and label target with its canonical schema key. No unexpected fields are removed or silently accepted on the backend. `validate_business` and its length/type/unknown-field rules remain unchanged.

## Verification

- Executed the submit function generated by the upstream Reflex tag `v0.10.0` in a Node VM: the old mapping reproduced six unexpected keys; the fixed mapping produced only the six schema keys and retained `Test Business`.
- Regression tests assert label/ID/name consistency, all six controls match the schema exactly, name-only submission works with blank remaining fields, and unknown keys including old aliases still fail.
- An actual Reflex component-tree test calls `_get_static_form_field_keys()` when Reflex is installed. That test is skipped in this execution environment, not reported as passed. Run the test suite in Codespaces to exercise it.
- No direct access to the live Codespace or post-fix browser round trip is claimed.
